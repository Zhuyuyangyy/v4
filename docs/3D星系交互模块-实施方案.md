# 3D 交互式星系 — 学习路径可视化模块实施方案

> 设计概念、架构规划与模块化执行清单。
> 品牌主题："知识宇宙"（呼应 DESIGN.md "星空观测站" 品牌北极星）

---

## 一、设计概念

### 核心隐喻

| 星系元素 | 对应业务概念 | 说明 |
|---------|------------|------|
| **恒星** (中心) | 学习总旅程 / 总目标 | 所有课程的汇合点，自转 + 脉动发光 |
| **星区** (constellation sector) | 课程领域 (CourseDomain) | 每个 domain 一个扇形区域，用不同色系区分 |
| **行星** | 学习阶段 (Phase) | 沿轨道绕恒星公转，大小/颜色表示阶段属性 |
| **卫星光点** | 阶段内节点 (Node) | 绕行星旋转，亮/暗表示完成状态 |
| **轨道环** | 阶段进度 | 环的发光填充比例 = 阶段完成度 |
| **星云粒子** | 背景氛围 | 数千个彩色粒子，深度雾营造宇宙感 |
| **中心光环** | 总进度 | 绕恒星的光环按总完成比例填充 |

### 状态 → 视觉映射

| 状态 | 星体表现 | 发光 | 透明度 | 交互响应 |
|------|---------|------|--------|---------|
| `completed` | 明亮饱满，光晕 | 强 (0.6) | 1.0 | 可点击，hover 放大 |
| `active` | 脉冲动画，进度填充 | 中 (0.3) | 1.0 | 可点击，hover 放大 |
| `available` | 静态可见，无动画 | 弱 (0.1) | 0.7 | 可点击，hover 放大 |
| `locked` | 灰暗轮廓，远处轨道 | 无 | 0.35 | 不可点击 |

### 品牌一致性

与 DESIGN.md "星空观测站" 北极星一致：
- 主色调沿用：极光青 `#00d4ff`、极光紫 `#7c3aed`、极光翠 `#06d6a0`、极光金 `#f59e0b`
- 设计系统要求"静态平坦，glow 只在交互态出现"，恒星持续发光属于品牌主题必须的视觉例外（欢迎页 badge-dot 同样持续发光）
- 不引入新色系，不增加装饰性光晕

### 持续发光例外说明

DESIGN.md "Static-Flat Rule" 规定光晕只在交互状态出现。星系场景中**仅中心恒星**作为例外允许持续发光（emissive + glowMesh），原因：
- 恒星是品牌隐喻的核心锚点（类比 Welcome 页 badge-dot 持续发光）
- 其他所有星体（行星、卫星、轨道环）遵守 Static-Flat Rule：仅 hover/active 时发光增强

CSS 变量补充（需在 `variables.css` 中新增）：
```css
--galaxy-panel-bg: #0c0c1a;        /* abyss-surface，与 clearColor 一致 */
--galaxy-border-color: rgba(0, 212, 255, 0.08);  /* 星系面板右侧分割线 */
```

## 二、架构概览

### 组件树

```
LearningPath.vue                    ← 页面容器，数据获取，双向同步
├── GalaxyPanel.vue                 ← 左侧面板容器 (sticky, 50%)
│   └── GalaxyScene.vue             ← Three.js 场景封装（核心渲染组件）
│       ├── entities/
│       │   ├── createParticles     ← 星云粒子系统
│       │   ├── createStar          ← 中心恒星
│       │   ├── createOrbitRing     ← 轨道环 (per phase)
│       │   ├── createPlanet        ← 行星 (per phase)
│       │   └── createSatellites    ← 卫星点 (per node)
│       └── composables/
│           ├── useGalaxyScene      ← 场景/相机/渲染器初始化
│           ├── useGalaxyControls   ← OrbitControls + 交互事件
│           └── useGalaxyAnimation  ← RAF 循环 + 动画调度
│
├── CourseOverview.vue              ← AI 课程概览（现有，位置调整）
├── QuickStats.vue                  ← 学习统计（现有，位置调整）
├── PhaseTimeline (inline)          ← 阶段时间线（现有，移入右栏）
└── BottomGrid (inline)             ← 本周目标 + 里程碑（现有，移入右栏）
```

### 数据流

```
phases (definitive source, 静态数据)
  → phasesToGalaxyData() 转换
    → GalaxyScene.props.galaxyData
      → Three.js 场景渲染

右侧 IntersectionObserver
  → activePhaseId (ref)
    → GalaxyScene.props.activePhaseId
      → 行星高亮更新

用户点击行星
  → emit('phase-click', phaseId)
    → scrollToPhase(phaseId) 右侧滚动
```

### 关键跨模块依赖（⚠️ 重要）

GalaxyScene.vue 内部维护一个 `galaxyEntities` 对象，用于跨模块共享实体引用：

```typescript
// GalaxyScene.vue 内部状态
interface GalaxyEntities {
  star: StarEntity | null
  planets: PlanetEntity[]      // ← 模块 11/12 的 Raycaster 需要此数组的 meshes
  orbitRings: OrbitRingEntity[]
  satellites: SatelliteEntity[]
  particles: ParticleSystemEntity | null
  css2dRenderer: CSS2DRenderer | null  // ← 模块 2 初始化，模块 11 添加标签
}
const galaxyEntities = reactive<GalaxyEntities>({
  star: null,
  planets: [],
  orbitRings: [],
  satellites: [],
  particles: null,
  css2dRenderer: null,
})
```

**模块间传递路径**：
- 模块 6-9（entities 创建）→ 将返回值存入 `galaxyEntities`
- 模块 11（Raycaster）→ 从 `galaxyEntities.planets` 取出 `.mesh` 做碰撞检测
- 模块 13（滚动同步高亮）→ 调用 `galaxyEntities.planets[i].setHighlight()` 切换状态
- 模块 14（动画循环）→ 遍历 `galaxyEntities` 所有 `.update()` 调用

**分层建议**：`galaxyEntities` 按职责拆分访问层，避免模块 11 和 13 误修改渲染状态：
```typescript
// 只读视图：Raycaster / 高亮同步 只需要 planets 的 mesh 引用和 setHighlight
const raycastTargets = computed(() => galaxyEntities.planets.map(p => p.mesh))
const planetHighlight = (phaseId: string, active: boolean) => {
  const p = galaxyEntities.planets.find(p => p.data.id === phaseId)
  p?.setHighlight(active)
}
```
模块 11 只依赖 `raycastTargets`，模块 13 只依赖 `planetHighlight`，都不直接操作 `galaxyEntities` 内部。

## 三、公共类型定义（所有模块共享）

以下类型是各 entities 函数的返回值接口，模块 6-9 的 entities 函数须遵守这些类型签名，以便在 GalaxyScene.vue 中统一管理。

```typescript
// ─── entities 返回值类型 ───

export interface StarEntity {
  mesh: Mesh                // 主球体
  glowMesh: Mesh            // 外发光层
  update: (dt: number, progress?: number) => void  // 自转 + 进度同步
  dispose: () => void
}

export interface PlanetEntity {
  mesh: Mesh
  satelliteGroup?: Group    // 卫星点组
  orbitAngle: number        // 当前公转角度（弧度）
  radius: number            // 轨道半径
  speed: number             // 公转速度
  data: GalaxyPhase         // 绑定的阶段数据
  update: (dt: number, activePhaseId?: string | null) => void
  setHighlight: (active: boolean) => void
  dispose: () => void
}

export interface OrbitRingEntity {
  line: LineLoop
  radius: number
  update: (progress: number, status: string) => void  // 进度 + 状态切换
  dispose: () => void
}

export interface SatelliteEntity {
  points: Points
  update: (planetPos: Vector3, dt: number) => void
  dispose: () => void
}

export interface ParticleSystemEntity {
  points: Points
  update: (dt: number, time: number) => void
  dispose: () => void
}

// ─── 相机初始位置 ───
// 相机从 (0, 8, 12) 位置俯视，FOV=50°
// 视角中心对准原点 (0, 0, 0)
// 这样所有轨道半径 3~7.5 的星体都在视野内


// ─── 星系数据映射类型 ───

export interface GalaxyNode {
  id: string
  name: string
  progress: number          // 0–100
  status: 'completed' | 'active' | 'available' | 'locked'
}

export interface GalaxyPhase {
  id: string
  title: string
  period: string             // 如 "第 1-4 周"
  progress: number           // 0–100
  status: 'completed' | 'active' | 'locked'
  color: string              // 阶段色（极光色系）
  nodes: GalaxyNode[]
}

export interface GalaxyDomain {
  id: string
  name: string               // 领域名，如 "AI"
  phases: GalaxyPhase[]
  color: string
}

export interface GalaxySceneData {
  domains: GalaxyDomain[]
  totalProgress: number      // 0–100，所有 phase progress 的加权平均
}
```

### 跨模块技术备注

**HMR 兼容性**：Vite 热更新时，GalaxyScene.vue 会重新挂载。canvas 元素会重建，Three.js 场景会走完整的 onUnmounted → onMounted 流程。这是正常行为，注意：
  - 不要在模块外部（如 store 或全局变量）保留对 scene/camera/renderer 的引用
  - 模块 4 的 OrbitControls 在 onUnmounted 中必须调用 `.dispose()` 并置 `controls = null`，否则 HMR 后残留的 controls 仍在驱动已销毁的 renderer.domElement
  - 所有 composable 返回的实例引用需通过 `ref` 或 `reactive` 持有，避免闭包捕获旧引用

**轨道环进度（setDrawRange 优化）**：预先创建完整 360° 的圆弧 BufferGeometry（64 segments），然后通过 `geometry.setDrawRange(0, Math.floor(64 * progress / 100))` 控制可见段数。更新进度时**不重建 geometry**，只改 draw range，性能远优于重建。

**完成光波的事件机制**：模块 14 的"完成光波"需要知道"某个节点 progress 刚变为 100"。在模块 10 的 watch 中对比 oldData 和 newData，检测到变化后调用一个回调或触发事件，模块 14 响应并播放光波动画。不在动画循环中轮询检测。

**右栏内容区**：使用 `display: flex; flex-direction: column; overflow: hidden` 包裹，内部内容区使用 `overflow-y: auto`。不硬编码 max-height，让 flex 自然分配剩余空间。

**CSS2D 标签渲染层级**：CSS2DRenderer 的 domElement 需要 `pointer-events: none` 避免阻挡 Raycaster 事件。标签内部文本不需要交互。
